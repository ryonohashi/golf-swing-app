# POC-02 リングバッファ

目的と合否基準は [`docs/poc/poc-02-ring-buffer.md`](../../docs/poc/poc-02-ring-buffer.md)。
ここにあるのは実験用のコードで、製品コードとして残す前提ではない。

| 場所 | 中身 |
|---|---|
| `POC02/` | 計測アプリ（iOS 18、実機のみ） |
| `POC02/RingBufferConfig.swift` | 暫定値。定数はここにだけ置く |
| `POC02/ChunkWriter.swift` | チャンク1つぶんの書き出し。チャンクの切り方の説明もここ |
| `POC02/ClipBuilder.swift` | チャンクの連結。連結方式の説明もここ |
| `POC02/Recorder.swift` | 撮影・チャンクの循環・トリガ・クリップの切り出し |
| `tools/summarize.py` | セッションの集計（Python 3.10 以上、標準ライブラリのみ） |

実打の判定は POC-01 の `HitDetector.swift` / `DetectionConfig.swift` / `AudioBlockMeter.swift` / `FrameMotionMeter.swift` を
`project.yml` からパスで参照している（コピーしていない）。判定の値を変える時は POC-01 側の `DetectionConfig.swift` を変える。

## 方式

```
カメラ（1080p/60fps 縦）＋マイク
  → 1秒ごとに別の AVAssetWriter でチャンクを書く（chunks/chunk_XXXXXX.mov）
  → 確定済みのチャンクを新しいほうから10個だけ残し、古いものを消す
トリガ（次の3つ、どれも「インパクト時刻 t」を決めるだけ）
  - 実打判定（POC-01 の動作＋インパクト音）
  - 手動トリガのボタン（押した時刻）
  - 間隔トリガ（一定間隔。連続打撃とクリップの重なりを試す）
  → t＋3秒までのチャンクが確定したら、[t−5秒, t＋3秒] に重なるチャンクをつなぐ
  → clips/NNN.mov として保存
```

- **チャンクの切り方**: 次のチャンク用の AVAssetWriter を別キューで先に `startWriting()` まで済ませて待たせておき、境界のフレームでは `startSession` と `append` だけを行う。境界は映像フレームの時刻そのもので、前のチャンクは `endSession(境界)` で閉じるので、フレームの抜けも重なりもない。新しいライタの最初のフレームは必ずキーフレームになる。待機中のライタが間に合わなかった境界は `standby_miss` として記録する
- **連結の方式**: AVMutableComposition に必要な範囲を並べ、AVAssetExportSession のパススルーで書き出す。再エンコードしないので速く、画質も落ちない
- **連続打撃**: クリップが重なっても、それぞれ独立に保存する（docs の案A）。切り出し待ちと連結中のクリップが使うチャンクは消さない
- **足りない場合**: 計測開始直後のトリガなど、前5秒ぶんのチャンクがない時は、あるぶんだけで作る。依頼した長さと実際の長さは両方ログに残る

## 1. ビルド（Mac）

```sh
brew install xcodegen
cd poc/poc02-ring-buffer
xcodegen generate
open POC02RingBuffer.xcodeproj
```

Xcode の Signing & Capabilities で Team を選び、iPhone を繋いで実行する。

## 2. 計測

### 2-1. 室内で先に確かめること（練習場の前に）

1. 「計測開始」→「間隔トリガ 4秒」をオンにして2〜3分回す。4秒ごとにクリップができ、隣どうしが4秒重なる（docs の例と同じ）
2. 「手動トリガ」を1秒おきに連打する。クリップが欠けずに全部できるか
3. 「計測終了」してから、クリップをいくつか写真アプリか QuickTime で開き、次を見る
   - 1秒ごとのチャンクの継ぎ目で、映像が止まったり飛んだりしないか
   - 継ぎ目で音がプツッと切れないか
   - シークとコマ送りが破綻しないか
4. 60分つけっぱなしにして、画面のチャンク数が10前後から増えないこと、使用量がクリップのぶんしか増えないことを見る

### 2-2. 練習場（POC-01 が通過してから）

1. 打席の後方2mに縦向きで置く。黄色の破線（POC-01 の動き検出の範囲）に全身が入る位置にする
2. 「計測開始」。以降は端末に触れない。画面の大きな数字が保存できたクリップ数
3. 普段のテンポで打つ。途中で、次の球をすぐに打つ速いテンポも混ぜる（8秒以内の連打）
4. 30〜60分続けてから「計測終了」。「保存中」の間は切り出し待ちのクリップを作っているので待つ

画面の「直近の所要時間」はインパクトから保存完了までの秒数。後ろの3秒を待つぶん、3秒より短くはならない。

## 3. ログの取り出し

「ファイル」アプリ → このiPhone内 → POC02 → `sessions/<日時>/` をAirDropなどでPCへ送る。Mac なら Finder の iPhone 画面の「ファイル」からも取り出せる。

| ファイル | 中身 |
|---|---|
| `clips/NNN.mov` | 切り出したクリップ（音声つき）。番号はトリガの順 |
| `chunks/` | 計測中のチャンク。終了時に空にする（`keepChunksAtEnd` を true にすると残る） |
| `config.json` | 計測時の設定（`ringBuffer` と、POC-01 の `detection`） |
| `meta.json` | 端末、フレーム数、落ちたフレーム数、チャンクの書き出し・削除・失敗の数、トリガの種類ごとの数、クリップの数と合計容量、終了時のフォルダ容量 |
| `clips.csv` | クリップ1本ごとの時刻、所要時間、依頼した範囲と賄えた範囲と実際の長さ、使ったチャンク数、抜けの数、ファイルサイズ、失敗の理由 |
| `chunks.csv` | チャンクの確定・削除・失敗（開始と終わりの時刻、フレーム数、サイズ、閉じるのにかかった時間） |
| `disk.csv` | 1秒ごとのチャンクのファイル数と容量、クリップのファイル数と容量、端末の空き容量 |
| `events.csv` | トリガ、音のピーク、動きの区間、実打、落ちたフレーム、待機中のライタの遅れ、発熱状態、エラー |

時刻 `t` はすべて、計測開始後の最初の映像フレームを0とした秒数（キャプチャの時計）。

`clips.csv` の主な列:

| 列 | 意味 |
|---|---|
| `impact_t` | インパクト時刻（実打判定の音の時刻／ボタンを押した時刻／間隔トリガの時刻） |
| `trigger_t` | トリガが確定した時刻。`detect_delay_s` = `trigger_t` − `impact_t`（実打判定にかかった時間） |
| `buffered_t` | 後ろの3秒ぶんのチャンクが確定し、連結を始めた時刻 |
| `done_t` / `latency_s` | クリップの保存が終わった時刻と、インパクトからの秒数 |
| `requested_s` / `covered_s` / `actual_s` | 依頼した長さ／ディスク上のチャンクで賄えた長さ／書き出したファイルの実際の長さ |
| `gaps` | 使ったチャンクの間の抜け（書き出しに失敗したチャンクなど）の数 |

## 4. 集計

```sh
cd poc/poc02-ring-buffer/tools
python summarize.py <セッションフォルダ>

# 許容する所要時間を変える（既定 5秒）。実際の長さが依頼よりどれだけ短ければ「短い」とするか（既定 0.05秒）
python summarize.py <セッションフォルダ> --max-latency 4 --short-tolerance 0.1
```

出るもの:

- クリップの保存数と失敗数、トリガの種類ごとの数。トリガの数とクリップの行数が合わなければ欠落として警告する
- インパクトから保存完了までの所要時間（全体とトリガの種類ごと）、実打判定の遅れ、連結と書き出しの時間
- 1クリップのファイルサイズと、1時間あたりのクリップ容量のペース
- チャンクのファイル数と容量の最大値（循環削除が効いていれば保持数の前後で止まる）、空き容量の最小値
- 失敗の一覧（クリップ、チャンク、エラー、落ちたフレーム、待機中のライタの遅れ）
- クリップごとの依頼した長さ・賄えた長さ・実際の長さ

合否は docs の基準に対応させて見る。

| 基準 | 見る数字 |
|---|---|
| インパクトから数秒以内にクリップが確定する | 所要時間の p90 と最大、`--max-latency` を超えたクリップ |
| 連続して打ってもクリップが欠落しない | 失敗数、トリガ数とクリップ数の一致、短いクリップ、`gaps` |
| 60分でディスク使用量が破綻しない | チャンクのファイル数と容量の最大値、1時間あたりのクリップ容量 |
