# POC-01: 実打の判定（動作＋インパクト音）

**このアプリで最大の技術リスク。ここが通らなければ撮影方式そのものを再設計する。**

先に製品UIを作らない。このPOCは実験用コードであり、製品コードとして残すことを前提にしない。

## 確かめること

「映像のスイング動作」と「インパクト音」のAND判定で、練習場の実環境で自分の実打／素振り／隣の打席の打球などを正しく分けられるか。

音だけで自分の打球を拾えるかは問わない。音の誤検知は映像で、映像の誤検知は音で捨てられればよい。判定方式は `spec-capture.md` を参照。

## 作るもの

判定してログを取るだけの最小アプリ。

- マイク入力を監視し、音圧ピーク（または帯域フィルタ後のピーク）のタイムスタンプと強度をログに残す。POCでは `AVAudioEngine` ではなく `AVCaptureAudioDataOutput` から音を取る。映像と同じ時計に揃い、参照動画の再生位置とログの時刻がそのまま一致するため
- カメラ映像に軽量な動き検出（ROI内のフレーム差分、optical flowなど）をかけ、動き量の時系列とスイング候補のタイムスタンプをログに残す
- 両者を時間窓で突き合わせた判定結果（実打／破棄）をログに残す
- 同時に通しの参照動画を1本録画しておく（後で正解データと突き合わせるため）
- 画面表示は実打と判定した回数のカウンタだけでよい

クリップの切り出しはこのPOCでは行わない（POC-02の範囲）。閾値や時間窓は後から変えて再解析できるよう、生のログを残す。

実装は `poc/poc01-hit-detection/`。ビルド、計測、ログの取り出し、再解析の手順はそこの README を参照。

## 測ること

練習場で次のケースを集める（回数は目安）。

| ケース | 回数 | 期待 |
|---|---|---|
| 自分の実打 | 50回 | 保存する |
| 自分の素振り | 20回 | 保存しない |
| 隣の打席の実打 | 50回 | 保存しない |
| ワッグル | 適宜 | 保存しない |
| アドレス調整 | 適宜 | 保存しない |

あわせて次も記録する。

| 項目 | 内容 |
|---|---|
| ボール出し機の音・会話・風 | 動き検出と重なって誤判定になるか |
| ダフり | マットの音が主体になる。実打として拾えるか |
| 打席による差 | 屋外／屋内、囲いの有無、隣の打席の人が画角に入るかで結果がどう変わるか |
| 1ショットあたりのピーク数 | クラブとボール、続いてクラブとマットで2回鳴る場合がある。デバウンス幅の決定に使う |
| 動き開始からインパクト音までの時間 | スイング候補の時間窓の決定に使う |
| 動き検出の負荷 | 常時稼働させた場合のCPU負荷・発熱への影響 |

## 合否基準

**自分の実打の保存率90%以上を保ったまま、素振り・隣の打席の実打・ワッグル・アドレス調整をまとめて、誤って保存する件数を自分の実打数の10%以下に抑えられる設定（閾値・時間窓）があること。**

10%は暫定値で、実測を見て見直す。

取りこぼしは誤保存より重い。閾値は取りこぼしを避ける側に寄せる。

複数の打席・複数の日で再現すること。1回うまくいっただけでは通過としない。

## やり方

1. 練習場で上のケースを集める。通しの参照動画を同時に録画しておく
2. ログのタイムスタンプと参照動画を突き合わせ、ケースごとの正解データを作る
3. 閾値と時間窓を変えながらログを再解析し、ケースごとの保存率を出す
4. 屋外・屋内、囲いの有無など条件を変えて再現性を確認する

## 通らなかった場合

どちらのセンサーが足を引っ張っているかを切り分ける。動き検出が原因ならVision姿勢推定を前段に寄せる余地を検討し、それでも通らなければ撮影開始方式そのものを見直す。手動モードは検出がうまくいかない環境の逃げ道として残すが、それを本来の使い方にはしない。

## 決まること

- 音の閾値の設計方針（固定値か、環境音からの相対値か）と帯域フィルタの要否
- 動き検出の方式とROIの取り方
- スイング候補とインパクト音を対応付ける時間窓
- デバウンス幅
- Vision姿勢推定を後段の確認に使う必要があるか
