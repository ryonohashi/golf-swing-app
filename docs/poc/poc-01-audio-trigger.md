# POC-01: インパクト音トリガ

**このアプリで最大の技術リスク。ここが通らなければ撮影方式そのものを再設計する。**

先に製品UIを作らない。このPOCは実験用コードであり、製品コードとして残すことを前提にしない。

## 確かめること

練習場の実環境で、自分の打球音だけを拾える閾値が存在するか。

## 作るもの

音を監視してログを取るだけの最小アプリ。

- `AVAudioEngine` でマイク入力を監視する
- 音圧ピーク（または帯域フィルタ後のピーク）を検知したらタイムスタンプと強度をログに残す
- 同時に通しの参照動画を1本録画しておく（後で正解データと突き合わせるため）
- 画面表示は検知回数のカウンタだけでよい

クリップの切り出しはこのPOCでは行わない（POC-02の範囲）。

## 測ること

| 項目 | 内容 |
|---|---|
| 自分の打球の検知率 | 実際に打った球数のうち、何％を検知できたか |
| 隣の打席の誤検知率 | 自分が打っていない時に何回鳴ったか |
| ボール出し機の音 | 誤検知するか |
| 会話 | 誤検知するか |
| 風のノイズ | 誤検知するか |
| クラブがボール以外に当たる音 | ダフった時はマットの音が主体になる。検知できるか |
| 打席による音響差 | 屋外／屋内、囲いの有無で閾値がどう変わるか |
| 1ショットあたりのピーク数 | クラブとボール、続いてクラブとマットで2回鳴る場合がある。デバウンス幅の決定に使う |

## 合否基準

**自分の打球の検知率90%以上を維持したまま、誤検知を自分の打球数以下に抑えられる閾値が存在すること。**

誤検知そのものは安い。前段で拾いすぎても、POC-02以降の動き確認で捨てられる。逆に自分の打球の取りこぼしは直接的な体験の毀損なので、閾値は取りこぼしを避ける方向に倒す。

複数の打席・複数の日で再現すること。1回うまくいっただけでは通過としない。

## やり方

1. 練習場で50球程度打つ。通しの参照動画を同時に録画しておく
2. ログのタイムスタンプと参照動画を突き合わせ、正解データを作る
3. 閾値を変えながらログを再解析し、検知率と誤検知率の関係を出す
4. 屋外・屋内、囲いの有無など条件を変えて再現性を確認する

## 通らなかった場合

音トリガ以外の撮影開始方式を検討し直す。その場合、本アプリの「端末に触れない」という前提から見直しが必要になる。

## 決まること

- 閾値の設計方針（固定値か、環境音からの相対値か）
- デバウンス幅
- 帯域フィルタの要否
