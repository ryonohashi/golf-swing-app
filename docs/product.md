# プロダクト定義

## 一文

打った1球を自動で動画に残し、自分で選んだ2球を重ねて、何が違ったのかをその場で見つけるiOSのゴルフフォーム比較アプリ。

## 価値の中心

AIがスイングを採点することでも、大量の動画を保存することでもない。
練習中の「撮影する・動画を探す・2本を選ぶ」という手間を極限まで減らし、自分の2球の違いを最短で見つけられることに置く。

## ターゲット

週1回以上練習場に通い、自分のスイングの変化を自分で確かめたい中級者。

## 示せること / 示せないこと

### 示せる

- 頭の移動量
- 肩の回転
- 腰のスウェー
- 体の傾き
- テンポ

### 示せない

- フェース角
- 打点（芯を食ったかどうか）
- ボールの行方

2D姿勢推定ではフェース角も打点も原理的に映らない。骨格が揃っていても球は曲がるし、少し崩れたフォームでナイスショットも出る。したがって「フォームが違う＝ミス」というロジックは成立しない。

アプリは原因を断定せず、2球の違いから原因候補を視覚的に絞り込むところまでを担う。

## 文言のルール

UI文言、コミットメッセージ、コード内コメントのいずれでも守る。

| 使わない | 使う |
|---|---|
| 原因を特定する | 違いを見つける / 原因候補を絞り込む |
| ミスを検出する | 動きの差分を表示する |
| 会心の1球 / ミスした1球 | 基準スイング / 比較する球 |
| AIが診断する | （v1に該当機能なし） |
| 直前の1球 | 最新球 |

「直前の1球」は今打った球の一つ前とも読めるため使わない。最新球で統一する。

基準スイングは「アプリが最良と判定した球」ではなく「ユーザー自身が比較の基準として選んだ球」である。UI上でもそう読める表現にする。

## 差別化

### 1. 手間の少なさ

既存アプリの多くは、1球ごとに録画ボタンを押し、あとからカメラロールで動画を探し、2本を選んで並べる、という手順を要求する。本アプリは打球音をトリガに1球ずつクリップが自動生成され、打った直後なら1タップで基準スイングと重ねられる。ユーザーが「探す」操作をほとんどしなくて済むことが違いになる。

### 2. 比較の基準の置き方

プロのスイングや理想フォームを正解として並べる設計には、既存アプリのレビューで「数日で役に立たなくなる」「自分のレベルに適応しない」という不満が出ている。本アプリはユーザー自身がピン留めした1球を基準にする。本人が選んだ球なら常に本人のレベルに合っている。
