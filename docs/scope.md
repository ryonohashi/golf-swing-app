# スコープ

## v1（今つくるもの）

完全ローカル・完全無料。ネットワーク通信なし。

```
撮る → 勝手に1球ずつ保存される → 最新球を基準スイングと1タップで比較 → 必要なら任意の2球を選んで比較
```

| 機能 | 内容 | 詳細 |
|---|---|---|
| 自動撮影（1球＝1クリップ） | 待機中はリングバッファで撮影・符号化し、自分のスイング動作とインパクト音がそろった時に実打と判定して、インパクト時刻の前後を1本のクリップとして確定する | `spec-capture.md` |
| 撮影モード | 自動（デフォルト）／手動。普段は選ばせない | `spec-capture.md` |
| 撮影成功の通知 | クリップ確定の瞬間に全画面カラーフラッシュと本数カウンタ | `spec-ui.md` |
| 構図ガイド | 固定の人型シルエット | `spec-capture.md` |
| 撮影アングル | 後方 / 斜め後方 / 横・正面をタグとして持つ | `spec-capture.md` |
| スイング一覧 | セッション内の全スイングをサムネイルで一覧表示 | `spec-compare.md` |
| 任意の2球の比較 | 比較の単位は任意の2球。ユーザーが選ぶ | `spec-compare.md` |
| 最新球のショートカット | 打った直後だけ「最新球 vs 基準スイング」を1タップで開く | `spec-compare.md` |
| 4コマ静止画比較 | アドレス / トップ / インパクト / フィニッシュ | `spec-compare.md` |
| 動画の重ね合わせ | 寒色・暖色のティント分け、手動スライダーで位置微調整 | `spec-compare.md` |
| 基準スイング | 自分で選んだ1球をピン留め。v1では1本 | `spec-compare.md` |
| クラブのタグ付け | ブロック単位で継承 | `spec-ui.md` |
| エクスポート | カメラロールへの書き出し | — |

### 実装順

最も安く価値が高いのは4コマ静止画比較。動画の重ね合わせより先に実装する。

## v1.1以降（将来やること）

v1の「撮影から比較まで」の基本体験が実際に成立することを確認してから着手する。

- 比較候補のおすすめ（自動判定ではなく、比べると良さそうな2球を提示する）
- 基準スイングとの自動比較
- 複数球のばらつき分析（残像重ね）
- セッションサマリーの自動生成
- 過去セッションとの自動比較、日をまたぐ比較のための自動位置合わせ
- 長期的な傾向の自動整理
- LLMによる言語化（観測事実と解釈を分けて提示する）
- 3D姿勢推定（`VNHumanBodyPose3DObservation`）
- ドリルの提案
- CloudKit同期とStoreKit2による課金
- クラブごとの基準スイング（複数ピン留め）

### 収益化の方向性（v1.1以降）

Freeを「自分で比較するための手動の分析ツール」、Proを「探す・選ぶ・整理する作業を肩代わりする自動化のパートナー」と位置づける。売るのは保存容量ではなく、比較・選別・分析にかかる手間と思考負荷の削減。

無制限保存・基準スイングの本数・保持期間・動画容量は課金価値としては弱く、主役にしない。

## 落としたもの

検討したうえで落としている。実装中に再提案しない。

| 落としたもの | 理由 |
|---|---|
| セッション全編の連続録画＋後処理での切り出し | 実装は簡単だが体験が破綻する。30分の録画は数GB規模になり、手に取った瞬間に数万〜十数万フレームの姿勢推定が始まって分単位で待たされる。「その場で2球の違いを見る」という主目的と衝突する |
| 異質な球の自動抽出 | 2D姿勢推定では、シャンクやフェースの開きの直接原因であるフェース角と打点が原理的に映らない。骨格が揃っていても球は曲がるし、崩れたフォームでナイスショットも出る。誤判定するとアプリが間違った診断を断定しているように見える。v1.1以降に「比較候補のおすすめ」として再検討 |
| 120fpsを前提にすること | 高フレームレートは発熱・電池・保存・処理のコストをすべて押し上げる。必要なのはインパクト前後のフォーム比較に足りる時間分解能であり、まず60fpsで実機検証する |
| 端末の持ち上げ検知による撮影の自動中断・再開 | 作らなくても壊れない。持ち上げれば人が写らなくなるだけで、戻せばまた写る。必要なのは電池対策だけなので、一定時間スイング候補がなければ省電力に落とすタイムアウトで足りる |
| 骨格上の矢印ヒント | ターゲットを中級者に定めたため「何が正しいか」を示す必要が薄い。数値の差分表示で代替でき、誤ったアドバイスを断定的に見せるリスクも消える |
| アウトライン（輪郭線）表示 | 人物セグメンテーションを毎フレーム実行する必要があり高価。寒色／暖色のティント分けならCIFilter一つで同じ判別性が得られる |
| 環境光センサーによる配色の自動切替 | iOSには環境光センサーの公開APIがない。手動の屋外トグル（設定を記憶）で代替する |
| 骨格ランドマークによる自動位置合わせ | 主用途を同一セッション内比較にしたことでカメラが動かず不要になった。日をまたぐ比較にだけ必要なので後回し |
| CloudKit同期・課金 | v1は端末内で完結させる。基本体験が成立することを確認してから着手する |
| Apple Watch連携 | 別ターゲットの追加とQAコストが大きい。動作＋インパクト音の判定で撮影が自動化されるため、リモート操作の必要性がない |
| 素振りの保存 | インパクト音がなく、クリップを切り出す基準の時刻が決まらない。動きのピークなどで代える案もあるが、実打と基準がずれて比較の前提が崩れる |
| コーチへの動画共有機能 | コーチ連携の複雑さを避ける |
| プロスイングとの比較用テンプレート | 著作権の問題。加えて「数日で役に立たなくなる」という既存アプリへの不満がある |
