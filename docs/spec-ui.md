# UI仕様

## モードは分けない

「練習モード（打席）」と「レビューモード（自宅）」で機能を分ける設計は採らない。打席で2球の違いを確かめることが主目的である以上、打席側の機能を削ると主目的そのものが果たせなくなるため。

機能はいつでも全部使える。日をまたぐ比較もクラブ間比較も4コマ比較も、打席で立ったまま実行できる。

特殊なのは「撮影中」という状態だけで、これは端末が2m先に置かれていて物理的に触れないという理由による。端末を手に持っている間は、打席でも自宅でも同じ画面・同じ機能とする。

## 撮影中（端末が手元にない状態）

| 項目 | 仕様 | 理由 |
|---|---|---|
| 撮影操作 | 端末に触れない。自分のスイング動作とインパクト音がそろった時に実打と判定し、1球分のクリップを確定する | 1球ごとに端末まで往復する運用は続かない。タイマー撮影は秒数に合わせて打つことになり、記録したい“いつものスイング”が別物になる |
| 動作中の表示 | クリップ確定時に全画面カラーフラッシュと本数の巨大カウンタ。2m先・直射日光下で読める大きさ、文字ではなく色と数字のみ | 端末は2m先にあり振動は伝わらず、打席は打球音で音も聞こえにくい |
| 誤検知の扱い | 軽量な動き検出でスイング候補を出し、その時間窓内のインパクト音で実打かを判定する。必要な場合のみVision姿勢推定で確認する。素振り（音なし）と隣の打席の打球（自分の動きなし）は保存しない | 練習場では他人の打球音が常時鳴っている。音だけでも映像だけでも判定しきれないため、互いの弱点を補わせる。毎回の姿勢推定は重すぎる |
| 撮影モード | 自動（デフォルト）／手動を設定から切り替える。普段は選ばせない | 検出がうまくいかない環境の逃げ道として手動を残す。素振りはクリップの基準時刻が決まらないため対象外 |
| 発熱・電池 | 画面は暗転。`ProcessInfo.thermalState` を監視し、深刻域ではバッファのfpsを落とす。一定時間スイング候補がなければ省電力状態に落とす | リングバッファでもカメラと符号化は回り続けるため、熱の問題は残る |

## 端末を手に持っている間（打席でも自宅でも共通）

機能の制限は設けない。変わるのは中身ではなく見え方だけ。

| 項目 | 仕様 | 理由 |
|---|---|---|
| 明るさ・配色 | 手動の屋外トグルで切替（設定を記憶。屋外＝明るい背景＋輝度最大、屋内＝ダーク可） | 直射日光下では暗色背景は反射して読めない。ただしiOSには環境光センサーの公開APIがなく自動判定はできない |
| タップ対象 | 主要操作（比較する、基準にする、クラブ変更）は56〜60pt。シークバーやコマ送り、不透明度スライダーのような精密操作は、見た目を細く保ったまま当たり判定だけを広く取る（細いトラックに60ptの透明な触り代を重ねる） | グローブ・片手・屋外で押せることは必要だが、全パーツを60ptにすると画面がUIで埋まり、肝心のスイング動画が圧迫される |
| 比較相手の選択 | 探させない。基準スイングを先に提示し、最新球との比較を1タップで開始できる状態にしておく。それ以外の2球はスイング一覧から選ぶ（比較候補の自動提示は行わない） | 打席で困るのは機能の多さではなく、小さなサムネイルから2本を探す操作。選択のコストを消せば機能を制限しなくてよい |
| 画面の向き | 縦＝重ね合わせ、横＝横並び。端末を回すと表示が切り替わる | 縦動画2本を縦画面に並べると細すぎて比較にならない |
| クラブのタグ付け | ブロック単位で継承する。一度設定すれば以降のスイングに自動適用し、変更時のみワンタップ | 同じ番手で20球続けて打つのが実際の練習。1球ごとの選択は破綻する |
| 記録の集計 | セッションごとの本数・クラブ別内訳は自動集計のみ。手入力は求めない | 打席で手入力させる余地はない |

## 撮影の向き

撮影は縦向き固定。レビューは回転対応。
