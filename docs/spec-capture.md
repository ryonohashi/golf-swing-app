# 撮影仕様

## 原則

**1球＝1クリップ。** セッション全体を1本の動画として保存しない。1球ずつのクリップが自動生成され、セッションの一覧に追加される。

ユーザーは撮影中に端末へ一切触れない。端末は打席の後方2m程度に、椅子やゴルフバッグに立てかけて置かれている前提で設計する。

## 実打の判定：動作と音のAND

音だけでは判定しない。**映像で「自分がスイングした」ことを確かめ、音で「実際にボールに当たった」ことを確かめる。** 両方がそろった時だけ実打として1球を保存する。

| ケース | 映像（自分のスイング） | 音（インパクト） | 結果 |
|---|---|---|---|
| 自分の実打 | あり | あり | 保存する |
| 自分の素振り | あり | なし | 保存しない |
| 隣の打席の実打 | なし | あり | 保存しない |
| ワッグル・アドレス調整 | 小さい／スイングに満たない | なし | 保存しない |

どちらのセンサーにも完璧は求めない。音の誤検知は映像で捨て、映像の誤検知（素振りなど）は音で捨てる。音検知の精度を100%にしようとしない。

カメラは打席の人に向いているので、人がスイングしているかは映像で見られる。ボールは遠くへ飛んでいくため、ボールそのものを映像で認識する必要はない。

### 状態遷移

```
待機
  ↓ 軽量な動き検出で「自分がスイングし始めた」
スイング候補
  ↓ 候補の時間窓内にインパクト音があった
実打として確定
  ↓ インパクト時刻を基準にリングバッファから切り出す
1球クリップ保存
```

スイング候補の時間窓内にインパクト音がなければ候補を捨てて待機に戻る。音だけ鳴って候補がない場合も捨てる。

### 処理の段階

Vision姿勢推定を毎フレーム回さない。

```
カメラ常時稼働（リングバッファに符号化）
  → 軽量な動き検出（ROI内のフレーム差分、optical flowなど）
    → 「スイングらしい」候補
      → 時間窓内のインパクト音を確認
        → 必要な場合のみ Vision 姿勢推定で確認
          → 実打確定 / 破棄
```

隣の打席の音だけでVisionが動くことはない。Visionが動くのは、自分の動きと音がそろった候補だけ。

取りこぼしは誤検知より重い。自分の打球を落とすと体験が直接損なわれるので、各段の閾値は取りこぼしを避ける側に寄せる。

### 検出時刻とクリップの切り出し

リングバッファで常に撮っているので、音を録画開始のトリガにしなくてよい。判定が確定してから、インパクト時刻の前5秒＋後3秒を切り出す（暫定値）。

```
過去5秒
───────────────●──────────
               ↑
             Impact
                               ─── 3秒
```

判定に多少時間がかかっても、バッファが保持している範囲内なら問題ない。

### デバウンス

1回のショットが2つのピークを生む場合がある（クラブとボールの衝突音、続いてクラブとマットの接触音）。1つのスイング候補に対するインパクト音は1回として扱う。幅はPOC-01で決める。

## 撮影モード

| モード | 保存条件 | 用途 |
|---|---|---|
| 自動（デフォルト） | 自分のスイング動作＋インパクト音 | 通常の練習 |
| 手動 | ボタン操作で1クリップずつ録画 | 音や動きの検出がうまくいかない環境 |

普段はモードを選ばせない。初期値は自動のまま使えるようにし、手動は設定から切り替える。

### 素振りは対象外

素振りは保存しない。インパクト音がないため、クリップを切り出す基準の時刻が決まらない。

## リングバッファ

未圧縮フレームを8秒ぶんRAMに保持するのではなく、短い動画チャンクを循環保存し、実打確定後に必要なチャンクを連結してクリップを確定する方式を採る。

未決事項（POC-02で決める）:

- チャンク長
- 前後に必要な秒数
- 連続打撃でクリップが重複した場合の扱い
- 後3秒を待っている間に次のスイング候補が来た場合の扱い

## 撮影アングル

3つのプリセットをタグとして持つ。アングルはクリップのメタデータに保存し、比較時に同じアングル同士を対応付ける。

| プリセット | 実現性 |
|---|---|
| 後方（Down the Line） | 自分の打席内で常に撮影可能。標準 |
| 斜め後方 | 自分の打席内で、後方から少し横にずらすだけで撮影可能 |
| 横 / 正面（Face On） | 隣の打席が空いている場合のみ。条件付き |

打席は仕切りで区切られていることが多く、横からの撮影は自分の打席の幅に収まらない。横／正面は「隣が空いた時のボーナス」として扱い、これが使えなくてもコア体験が途切れない設計にする。

動き検出のROIはアングルごとに変わりうる。特に横／正面では隣の打席が画角に入りやすい。

## 構図ガイド

固定の人型シルエットを画面に重ね、全身が収まる位置に端末を置けるようにする。

前回撮影時のフレームを使った位置合わせガイドはv1.1以降。同一セッション内の比較では端末が動かないため、v1では固定シルエットで足りる。

## 向き

撮影は縦向き固定。ゴルフの後方撮影は縦向きが適切という撮影ガイドの推奨とも一致する。

## 発熱・電池

リングバッファでもカメラと符号化は回り続けるため、連続録画をやめても熱の問題は残る。消えるのはストレージと後処理時間であって熱ではない。動き検出も常時回るため、その負荷も含めて測る。

- 撮影待機中は画面を暗転する
- `ProcessInfo.thermalState` を監視し、深刻域ではバッファのフレームレートを落とす
- 一定時間スイング候補がなければ省電力状態に落とす（端末の持ち上げ検知は実装しない）

60〜90分のカメラ稼働時の発熱と電池消費は実機で測定する（POC-03と合わせて実施）。

## 参考

音と映像を組み合わせる方式は既存製品でも使われている。

- LiveViewSports: AIによるスイング検出と音を組み合わせるHybrid方式を推奨している（https://liveviewsports.com/pages/lvprodsm-recording）
- YAMAHA PLAY SWING: 音と映像でインパクトを検出し、素振りなどを除外している
- GolfRec: 保存対象を ball strikes / practice swings / both から選べる（https://apps.apple.com/jp/app/golfrec-golf-swing-analyser/id1640216792）
