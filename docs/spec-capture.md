# 撮影仕様

## 原則

**1球＝1クリップ。** セッション全体を1本の動画として保存しない。打球音をトリガに、1球ずつのクリップが自動生成され、セッションの一覧に追加される。

ユーザーは撮影中に端末へ一切触れない。端末は打席の後方2m程度に、椅子やゴルフバッグに立てかけて置かれている前提で設計する。

## 撮影の流れ

```
1. 待機中はリングバッファで撮影・符号化する
2. AVAudioEngine でインパクト音のピークを監視する
3. 検知した時点で、前5秒＋後3秒程度を1本のクリップとして確定する（暫定値）
4. 誤検知フィルタを通す
5. セッション内の1球として一覧に追加し、全画面フラッシュで通知する
```

秒数・バッファ長はすべて暫定値であり、POC-02で確定する。定数は設定として1箇所にまとめる。

## リングバッファ

未圧縮フレームを8秒ぶんRAMに保持するのではなく、短い動画チャンクを循環保存し、トリガ後に必要なチャンクを連結してクリップを確定する方式を採る。

未決事項（POC-02で決める）:

- チャンク長
- 前後に必要な秒数
- 連続打撃でクリップが重複した場合の扱い
- 後3秒を待っている間に次の打球音が来た場合の扱い

## 誤検知フィルタ

練習場では隣の打席の打球音、ボール出し機の音、会話、風が常時鳴っている。毎回Vision姿勢推定を回すのは重すぎるため、二段構成にする。

```
音トリガ
  → 軽量な動き確認（フレーム間差分など）
    → 必要な場合のみ Vision 姿勢推定
      → スイング成立 / 破棄
```

誤検知そのものは安い。前段で拾いすぎても、後段で捨てられれば実害は小さい。逆に自分の打球を取りこぼすのは致命的なので、閾値は取りこぼしを避ける方向に倒す。

### デバウンス

1回のショットが2つのピークを生む場合がある（クラブとボールの衝突音、続いてクラブとマットの接触音）。短いデバウンス窓を必ず設ける。幅はPOC-01で決める。

### 既知の制約

素振りは音が出ないため記録されない。これは意図した挙動とする。

## 撮影アングル

3つのプリセットをタグとして持つ。アングルはクリップのメタデータに保存し、比較時に同じアングル同士を対応付ける。

| プリセット | 実現性 |
|---|---|
| 後方（Down the Line） | 自分の打席内で常に撮影可能。標準 |
| 斜め後方 | 自分の打席内で、後方から少し横にずらすだけで撮影可能 |
| 横 / 正面（Face On） | 隣の打席が空いている場合のみ。条件付き |

打席は仕切りで区切られていることが多く、横からの撮影は自分の打席の幅に収まらない。横／正面は「隣が空いた時のボーナス」として扱い、これが使えなくてもコア体験が途切れない設計にする。

## 構図ガイド

固定の人型シルエットを画面に重ね、全身が収まる位置に端末を置けるようにする。

前回撮影時のフレームを使った位置合わせガイドはv1.1以降。同一セッション内の比較では端末が動かないため、v1では固定シルエットで足りる。

## 向き

撮影は縦向き固定。ゴルフの後方撮影は縦向きが適切という撮影ガイドの推奨とも一致する。

## 発熱・電池

リングバッファでもカメラと符号化は回り続けるため、連続録画をやめても熱の問題は残る。消えるのはストレージと後処理時間であって熱ではない。

- 撮影待機中は画面を暗転する
- `ProcessInfo.thermalState` を監視し、深刻域ではバッファのフレームレートを落とす
- 一定時間トリガがなければ省電力状態に落とす（端末の持ち上げ検知は実装しない）

60〜90分のカメラ稼働時の発熱と電池消費は実機で測定する（POC-03と合わせて実施）。
